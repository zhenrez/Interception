# Interception operating contract

## Goal and scope
Make supported inference calls wait for a manually supplied answer and resume correctly.
Keep each project's authority, brief, mailbox and evidence separate. The source repository
is not the private inference mailbox. Panoptes and ARTTOO are separate projects.

## Before mutation
- Read the owner's current instructions, README, docs/architecture.md, START_HERE.md and
  relevant plugin setup. Recover branch heads, holds and superseded decisions.
- State the intended delta and evidence of success. Distinguish planning-only authority
  from implementation authority. Do not turn a new idea into an architecture replacement.
- Retrieve material missing decisions; do not guess. Continue non-mutating diagnosis when blocked.

## Execute bounded work
- Reuse the existing launcher and bridge. Do not expand the assessor without a specific
  failing target requirement. Do not elect optimizers based on ease of integration.
- Preserve requested-model provenance; manual inference is not requested-provider execution.
- No hidden paid fallback, global SDK patch, arbitrary stack-restoration claim or auto-execution
  of commands supplied in RETURN. Validate before releasing a caller.
- Resolve routine implementation choices; ask the owner only for material missing decisions/access.

## Before reporting completion
- Test the exact revision and name the boundary: unit, local caller round trip, remote relay,
  real Windows desktop, or complete host workflow. One does not prove the others.
- Inspect the distributable. Include the test target, license, launcher and operating procedure.
- Hand over the actual artifact, not merely a claim that an Actions artifact exists.
- Record remaining blockers and the next bounded step. A CATCH/RETURN completion is not
  evidence that the enclosing project or integration is finished.
